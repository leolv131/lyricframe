# LyricFrame 工作流（v3.1）

> 给一首现成的歌做动画 MV：**AI 不调用视频生成模型，而是写代码逐帧画出画面**，再用 ffmpeg 配上原曲。角色由代码绘制，全片不会变脸；每一帧只由时间 `t` 决定，任何一段都能单独重画。
>
> 这份文档是给 AI 助手（Claude、Codex 等）和想了解流程的人看的。AI 的执行手册是仓库根目录的 [`AGENTS.md`](../../AGENTS.md)，两者内容一致。

## 核心原则

1. **先准，再深。** 每一句歌词都要有一个观众一眼看懂的具体画面；"深一层"的立意藏在故事里，不另造一套需要观众去解码的象征系统。
2. **准之后要美。** 用色板讲时间，高潮敢留白，关键物件单独精修。
3. **先有光，再有物；少切、远看、一直在动；一首歌只用一套比喻。**
4. **主角任何时候都必须一眼看清。** 氛围不能以牺牲人物为代价。

这些原则来自对多支口碑好的 AI MV 的逐帧对比，原因和数据见文末「附录：规则从哪来」。

---

## 总览

```
0 准备素材 → 1 歌词时间轴 ✋ → 2 故事 ✋ → 3 逐句画面表 ✋ → 4 分镜 ✋
→ 5 风格与情感样片 ✋ → 6 分章制作 → 7 合成检查 ✋ → 8 交付包装
```

✋ = 停下来，把结果给用户看，等用户确认后再进入下一步。

| 步骤 | 做什么 | 产出 |
|---|---|---|
| 0 准备素材 | 拿到音频和歌词文件；确认片长、画幅、风格 | `project.json` |
| 1 歌词时间轴 ✋ | 逐句开唱时间；节拍、段落、能量曲线 | `timing.json`、`MUSIC_MAP.md` |
| 2 故事 ✋ | 整体理解 → 一个具体的故事 → 一套比喻 → 色板 | `STORY.md` |
| 3 逐句画面表 ✋ | **每句歌词一个画面钩子**（最关键的一步） | `LYRIC_SHOTS.md` |
| 4 分镜 ✋ | 时间、景别、运镜、卡点、必须看得见的元素 | `STORYBOARD.md` |
| 5 风格与情感样片 ✋ | 画风规范、角色设定、一个 5–8 秒的情感镜头 | `STYLE_GUIDE.md`、样张、样片 |
| 6 分章制作 | 分章写代码、渲染 720p 预览、逐镜对照 | `src/`、章节预览 |
| 7 合成检查 ✋ | 1080p 正式渲染、配原曲、自检清单、量化指标 | 成片初版、检查图 |
| 8 交付包装 | 干净版 + 字幕版、封面、可选对比拼接和文案 | 成片、封面、字幕包 |

**两种节奏**

- 默认：每个 ✋ 停下等确认。
- 用户说"不用停，直接出成品"：每一步的文档照写，一口气做完，最后一起交付；用户看完再提修改。

**默认片长**：先做 30–60 秒（一段主歌 + 一段副歌）。用户满意后再做完整版。完整版 4 分钟左右的歌，制作要几个小时。

## 第 0 步：准备素材

向用户要（缺的就问，一次问清）：

1. **音频**：mp3 / m4a / wav / flac 都可以，也可以是带音轨的视频。
2. **带时间的歌词文件（.lrc）**：推荐去 [lrclib.net](https://lrclib.net) 搜歌名下载，免费、不用注册。没有 .lrc 也能做，第 1 步会用语音识别找时间。
3. 三个选择（用户不说就用默认值）：
   - **片段还是完整版**：默认片段，挑副歌所在的 30–60 秒
   - **画幅**：默认 16:9 横屏 1920×1080；竖屏 1080×1920 用于抖音 / 短视频
   - **风格**：`pixel8bit`（8bit 像素）或 `flatq`（扁平 Q 版）；用户没想法就按歌的气质推荐
4. 可选：歌词解读、喜欢的参考 MV、想要的故事方向。

产出 `project.json`：歌名、原唱、音频路径、片段起止、画幅、风格、输出目录。

### 版权规则（整个流程都要遵守）

- **AI 不写出、不复述、不经手歌词原文。** 歌词文字只在用户电脑或沙盒里的脚本之间流转（`.lrc` → 字幕文件），AI 读取的是**时间**和**句号**。
- 需要讨论某一句时，用"第 7 句""副歌第二句"或**内容要点**（自己的话转述），不要引用原词。
- 原曲音频只用于用户自己的作品配乐，不放进公开仓库或模板里。
- 画面上**不放歌词字幕**；需要字幕时，由第 8 步的工具把用户的 .lrc 烧进视频，AI 不碰文字。

## 第 1 步：歌词时间轴 ✋ → `timing.json` + `MUSIC_MAP.md`

**1.1 逐句时间**

- 有 .lrc：运行 `python tools/lyrics_timing/lrc_timing.py assets/song.lrc --audio assets/song.mp3 --out work/`
  - 生成 `timing.json`（只有句号和起止时间，没有歌词文字，AI 只读这个）和 `lyrics.srt`（给第 8 步烧字幕用，AI 不读）。
  - 工具会对比 .lrc 时间和音频里人声的起点，报告整体偏移；偏移超过 0.3 秒时自动校正，并在报告里写明。
- 没有 .lrc，或 .lrc 和这版音频对不上（现场版、翻唱、剪辑版）：用 `tools/lyrics_timing/align_asr.py`（语音识别对齐，见工具说明；第一次运行要下载模型）。
- 重复的副歌也要逐条列出，不要合并。

**1.2 节拍与段落** → 运行 `python tools/lyrics_timing/music_map.py assets/song.mp3 --timing work/timing.json`

- 输出 BPM、节拍网格、每 4 秒的能量曲线、建议的段落边界（前奏、主歌、导歌、副歌、桥段、尾奏）。
- 注意：慢歌常被测成双倍速（例如 72 BPM 测成 144），用常识判断。
- AI 据此写 `MUSIC_MAP.md`：段落表（段落、起止、包含的句号、**内容要点**、剪辑节奏建议）+ 关键卡点表 + 能量曲线。模板见 `templates/MUSIC_MAP.md`。

✋ **确认**：段落划分对不对、时间卡得准不准。可以渲染一个叠了字幕的静帧视频给用户核对（`tools/lyrics_timing/preview_timing.py`）。

## 第 2 步：故事 ✋ → `STORY.md`

**2.1 整体理解**

- 这首歌在讲什么、谁在对谁说、情绪怎么起伏。可以查网上的歌词解读和创作背景。
- 标出**本身就有画面的词**（名词、动作、地点）和**抽象的句子**（需要发明比喻的）。

**2.2 一个具体的故事**

- 一句话立意可以有，但要藏在故事里，**不能靠观众解码**。
- 故事回答：**谁、在哪、发生了什么**。优先用具体的生活场景（咖啡馆、公交站、出租屋、花店），少用纯抽象空间（星河、虚空、幕布）。
- 设计 2–3 个情感高点，标出时间。
- 角色清单：每个角色的固定特征；**信物**（贯穿全片的一件小东西，如红气球、蓝蝴蝶发夹）。

**2.3 一套比喻（视觉语法）**

- 全片只用**一套**观众一看就懂的语言，让抽象句有地方落。例如：
  - 游戏机制：HP、GAME OVER、存档、CONTINUE?
  - 计数器：日历撕页、DAY 计数、"告白进度"格子
  - 物理隐喻："颜色 = 存在感"（被忽视的人变灰变透明，她靠近时颜色流回来）
- 检验：**不看解释，路人能不能看懂**。看不懂就换。
- 常驻界面（HUD）默认关；需要时只在关键时刻出现几秒，用章节卡做结构。

**2.4 色板即叙事**

- 每个时空 / 情绪锁定 4–8 色（回忆、现在、高潮各一套）。
- **色板切换落在情绪高点**（通常是副歌第一拍）。
- 留一个全片唯一的高饱和色给信物。

**2.5 3–4 个核心场景**

- 选 3–4 个地方，做出纵深、灯光、细节，在不同时间、天气下反复出现（同一条巷子：雨夜 / 放晴 / 黄昏）。比每句换一个新地方好看得多。

✋ **确认**：故事、角色与信物、比喻、色板、核心场景、情感高点。

## 第 3 步：逐句画面表 ✋ → `LYRIC_SHOTS.md`（最关键）

每一句（用句号指代，不写原词）写一行：

| 句 | 时间 | 内容要点 | 画面钩子 | 场景 | 角色动作 / 表情 | 段落 |
|---|---|---|---|---|---|---|
| 07 | 0:44.2–0:47.6 | （自己的话转述） | 一把大剪刀剪断行李带，小物件散了一地 | 产房，无影灯 | 小人伸手去抓，头顶冒"！" | 主歌 1 |

规则：

- **画面钩子**：把这句里的名词或动作变成一个**具体、有趣、一眼认得出**的物件或动作。本身有画面的直接画准；抽象的用第 2 步那套比喻。
- **同一句重复出现时换新钩子**，不复用画面。
- 整张表连起来是一个连贯的故事，不是一堆单句插画。
- 前奏、间奏、尾奏也要写，用来推进故事或回顾。
- 每段至少一个**互动式钩子**（选项框、打字又删掉的对话框、读档、道具弹窗）。
- 抽象句用全片那一套比喻；具体句用环境变化表达，不要一句一个道具 / 文字贴纸。**画面上的字砍掉八成。**

**自检**：遮住"内容要点"列，只看"画面钩子"，情绪和意思对不对得上。不要求每句都猜得出原词；宁可一段一个强画面，不要一句一个贴纸。

✋ **确认**：逐句过一遍，重点看抽象句的处理。

## 第 4 步：分镜 ✋ → `STORYBOARD.md`

| 镜 | 时间 | 时长 | 句 | 画面钩子 | 景别 | 运镜 | 卡点 | 必须看得见 |
|---|---|---|---|---|---|---|---|---|

- **按乐句切**：镜头平均 6–8 秒；一句一镜或两句一镜。副歌高潮可以 2–4 拍一切，但要有长镜头。
- **景别**：远景只交代环境；**主角戏用中景**；情感句给近景 / 特写。同一景别不连续超过 2 镜。
- **卡点**：剪切卡点（换镜头，落在开唱拍上）+ 镜内卡点（重拍时灯亮、物件弹出）。
- **节奏曲线**：主歌可以密；副歌敢留白，至少一个 3 秒以上的长镜头或大场景。一段只放一个最重要的情感动作。
- **必须看得见**：每镜写清楚观众必须看到的元素，第 6 步逐条对照。
- **动态清单**：每镜写"什么在一直动"（视差层、粒子、雨雪、车船、灯闪）。没有就不算完成。

✋ **确认**：节奏、景别变化、长镜头位置。

---

## 第 5 步：风格与情感样片 ✋ → `STYLE_GUIDE.md` + 样张 + 样片

**5.1 选风格：先过"情感测试"**

角色必须能做**表情**（哭、笑、脸红、惊讶）和**肢体表演**（拥抱、伸手、跌倒）。本项目自带两套：

| 风格 | 目录 | 适合 | 技术 |
|---|---|---|---|
| 8bit 像素 | `styles/pixel8bit` | 怀旧、游戏感、甜歌、叙事歌 | Python + numpy + Pillow，320×180 放大 6 倍 |
| 扁平 Q 版 | `styles/flatq` | 日常、城市、轻快的歌 | Python + skia，1920×1080 矢量 |

皮影、剪纸、水墨演不了情感，只适合做片中片、回忆段、转场。照片级写实代码画不出来，不在本流程范围内。

**5.2 规范**（写进 `STYLE_GUIDE.md`，模板见 `templates/`）

- 每种情绪 / 时空的色板、光源规则、纹理。
- 表情库：每个主要角色至少 6 种表情 + 头顶符号（? ! ❤ 汗 泪）。
- 场景：前、中、背景三层，至少 3 件道具，至少一样东西在动。
- 人物尺寸：远景头高 14、中景 24–34、近景 44、特写 ≥ 36（像素风；头高 ≥ 36 自动启用精细五官）。

**5.3 样张与样片**

- 角色设定图（正面 / 表情表）、3–4 张关键帧样张。
- **一个 5–8 秒的完整情感镜头样片**（例如"她推开窗看见气球"），确认情感演得出来再开工。

✋ **确认**：画风、角色、样片。

## 第 6 步：分章制作

**先布光，再画物**

1. 每个场景先定光源（位置、颜色、强度）和环境光。
2. 再放建筑、人物、道具。
3. 最后加光晕、倒影、粒子。
4. 人物在光照之后**单独合成**，亮度保底（像素风 `floor=0.55–0.9`），加轮廓光，保证暗场里也看得清（`styles/pixel8bit/stage.py`）。

**布光规则**

- 抒情歌默认暗调；每个场景至少 1 个可见光源（带光晕）；天空 ≥ 3 层渐变；有水 / 玻璃就做倒影。
- **灰 ≠ 忧郁。忧郁 = 暗底上的一点暖光。**
- 甜歌不压暗：白天保持亮色，只给黄昏和夜景布光。

**工程结构**

```
projects/<歌名>/
├─ project.json
├─ work/timing.json         只有时间，没有歌词
├─ MUSIC_MAP.md  STORY.md  LYRIC_SHOTS.md  STORYBOARD.md  STYLE_GUIDE.md
├─ src/
│  ├─ lf_path.py            把 styles/<风格> 加入路径
│  ├─ common.py             本片共用：色板、角色外观、场景零件
│  ├─ ch1.py … chN.py       每章一个文件，每镜一个函数 shot(t, D)
│  └─ make.py               只列镜头；渲染选项见 tools/lf_make.py（整片 / 片段 / 单帧 / 720p 预览 / 镜头表）
└─ out/                     预览、检查图、成片
```

按画风复制 `templates/starter-pixel8bit/` 或 `templates/starter-flatq/` 开始（已经能直接渲染，有布光、人物合成、示范镜头）；两个完整案例见 `examples/`。

```bash
python src/make.py --still 12.5               # 单帧 -> out/stills/
python src/make.py --preview --subs           # 720p 预览 + 叠字幕的预览（只给用户看）
python src/make.py --jobs 4                   # 1080p 成片 -> out/final.mp4
```

**每章的流程**

1. 写完一章就渲染 **720p 预览**发给用户，有问题只返工该章。
2. 预览里**叠字幕**（`make.py --preview --subs`，只在预览里叠，成片不叠），方便用户判断"这句唱的时候画面对不对"。
3. **逐镜对照**（交付预览前必须做）：`python src/make.py --shots-json` 导出镜头表，再 `python tools/review/shot_check.py out/预览.mp4 --shots out/shots.json --offset <起>`，每镜取中间一帧拼成检查图，和分镜的"必须看得见"逐条对照；缩到手机大小看一遍。写了没画出来、画了看不清的，当场返工。
4. **美术精修**：信物、手、信件等关键道具单独精修；背景加纹理和手工细节（招牌、杂物、晾晒），不留大片纯色；检查色板。

**并行**：支持子代理的环境（如 Claude Code），可以在 `STYLE_GUIDE.md` 和 `common.py` 定好后，按章分给多个子代理并行写，最后统一渲染。

## 第 7 步：合成检查 ✋

1080p 正式渲染、拼接、配原曲。然后跑：

```bash
python src/make.py --jobs 4                    # 片段范围和音频读 project.json
python tools/review/metrics.py out/final.mp4            # 五项量化指标
python tools/review/contact_sheet.py out/final.mp4      # 均匀抽 20 帧拼图
python tools/review/subtitle_safe.py out/final.mp4 --timing work/timing.json --offset <起>   # 字幕遮挡检查
```

**自检清单**（完整版见 [`checklist.md`](checklist.md)）

- [ ] 每句歌词都有对应画面；重复句换了新画面
- [ ] 主角在每个镜头里都一眼看得清（缩到手机大小检查）
- [ ] 每个剪切点落在节拍上；按乐句切，镜头平均 5–9 秒
- [ ] 每个镜头里一直有东西在动
- [ ] 景别有变化，没有连续好几镜同一构图
- [ ] 角色五官、配色前后一致；情感镜头有表情
- [ ] 色板切换落在情绪高点；信物颜色全片一致
- [ ] 副歌有呼吸（至少一个长镜头）
- [ ] 有人声时，底部字幕安全区（横屏 170px / 竖屏 300px）里没有界面文字、人脸、手部动作、信物
- [ ] 转场无黑帧、无跳帧；音画时长一致，首尾淡入淡出
- [ ] 看一眼量化指标（见下表），标 `look` 的项想清楚是不是有意为之

**量化指标**（`metrics.py` 输出）

指标是**参考值**，不是及格线：数字来自几支口碑好的 AI MV；甜歌、粉彩风天然偏亮、偏淡，不必硬压。工具在偏离参考值的项旁边标 `look`，意思是"值得看一眼"。

| 指标 | 含义 | 参考值 |
|---|---|---|
| 暗场帧占比 | 平均亮度 < 50/255 的帧 | 抒情 / 暗调歌 ≥ 30%（参考片 36–53%）；甜歌不看 |
| 平均饱和度 | | ≥ 0.40（参考片约 0.53；粉彩风会低一些） |
| 镜头内动态（中位数） | 同一镜头里相邻帧的变化 | ≥ 1.0（参考片 1.1–1.9） |
| 几乎不动的秒数占比 | | ≤ 20%（参考片 20–23%） |
| 平均镜头时长 | 自动检测剪切点 | 5–9 秒，按乐句切 |

✋ **确认**：给用户看成片初版、20 帧拼图和指标。

## 第 8 步：交付与包装

- **成片**：干净版（不带字幕）。
- **字幕版**（可选）：`python tools/lyrics_timing/burn_subtitles.py out/final.mp4 work/lyrics.srt --style pixel --offset <起>`。字幕文字来自用户的 .lrc，AI 不经手。字幕样式跟画风走：像素风用点阵字 + 半透明底框；Q 版用思源黑体粗 + 深色描边。
- **封面**：从全片最好看的一帧加片名和署名，横版 16:9；需要时出抖音竖版 9:16 / 3:4（`tools/package/douyin_cover.py`）。
- **署名**：片头 / 片尾和封面写 `原唱 · <歌手>`；片尾一句收尾（谢谢观看 / THANKS FOR WATCHING），字体跟画风走。
- **对比拼接**（可选，例如两个 AI 做同一首歌）：`python tools/package/stack_compare.py 上.mp4 下.mp4 out.mp4`，上下拼成 1920×2160，只保留一条音轨。
- **短视频文案**（可选）：默认"测评干货型"——说清用了什么方法、和别的版本比强在哪、一个具体的数字（镜头数、制作时长）。

## 附录：规则从哪来

v1 到 v3.1 的规则，来自作者把自己做的 MV 和网上同名的 AI MV 逐帧对比（各均匀抽 20 帧，量画面指标）：

| 指标 | 别人的《小镇姑娘》 | 我们 v2 | 别人的《蝴蝶》 | 我们 v2 |
|---|---|---|---|---|
| 暗场帧占比 | 53% | 16% | 36% | 6% |
| 平均饱和度 | 0.54 | 0.43 | 0.53 | 0.29 |
| 镜头内动态（中位数） | 1.9 | 0.5 | 1.1 | 0.8 |
| 几乎不动的秒数占比 | 20% | 32% | 23% | 32% |
| 镜头数 | ≈32 | ≈70 | ≈57 | 72 |

结论：**歌词翻译已经不差，差在光、镜头和克制。** 由此得到 v3 的规则：先布光、按乐句少切、镜头里一直在动、一首歌一套比喻、3–4 个核心场景反复出现。

v3.1 的修订：第一版 v3 样片把"远景、小人物、剪影"做过头，人物只有 14–40 像素高、暗底暗人，完全看不清，比旧版还差。于是改成：环境用 v3 的布光和长镜头，人物回到 Q 版中景尺寸，光照后单独合成并保底亮度。**任何时候主角必须一眼看清。**

更早的教训（v1 → v2）：用皮影 + 自创隐喻做《我记得》，立意好，但观众看不懂、皮影演不了情感、分镜里写的东西渲染出来看不见。由此加入了逐句画面表、情感样片和逐镜对照。
